API Gateway ── 入口での認可とティア制御

Client → API Gateway → Lambda（分離モード）

役割 2 つ

  • Lambda Authorizer: トークン検証 → tenantId を解決し下流へヘッダー伝播（信用できる tenantId を配る）
  • Usage Plans ＋ API Keys: テナント / ティア別のスループット・クォータ（ノイジーネイバー対策・使用量計測）
API 入口でやることは2つ。Authorizer で tenantId を解決して下流 Lambda へ X-Amz-Tenant-Id 等でマッピング。Usage Plans でティア別のレート / クォータ制御。 認証〜コンピュートが tenantId で1本の線に繋がる。 ボイラープレートの実例: REQUEST 型 Lambda Authorizer に認可を集約。Host 由来 tenantId（信用しない）と JWT 由来（信用する）を突合し、正を JWT に寄せる。信用できる tenantId を1か所で確定する実装例。
