IAM + STS ── プラットフォームで強制（ABAC）

JWT の tenantId → STS session tag → IAM ポリシー ${aws:PrincipalTag/TenantID} → リソースがテナントスコープに限定

例: arn:aws:s3:::bucket/${aws:PrincipalTag/TenantID}/*

強み: ロールが増えない（1 万テナントでもロール 1 本、タグで動的にスコープ）

Cognito で載せた tenantId を AWS プラットフォーム側の実行時強制に落とすのが IAM + STS。アプリのバグがあっても IAM が最後に止める層。 公式の3方式（動的生成ポリシー / RBAC / ABAC）のうち本命は ABAC。 AssumeRole + session tags、または JWT の https://aws.amazon.com/tags クレームを使う AssumeRoleWithWebIdentity で TenantID をセッションタグ化。 「自テナントのプレフィックスしか触れない」がポリシー評価の時点で強制される。
