9. 配信・エッジ: テナントをどう振り分けるか

CloudFront マルチテナントディストリビューション

{tenant}.example.com → connection group → distribution tenant（ブループリント継承）→ テナント別オリジン

  • 3 要素: multi-tenant distribution（ブループリント）／ distribution tenant ／ connection group
  • ワイルドカードサブドメイン ＋ ワイルドカード証明書を 1 回設定 → テナント追加時に DNS も証明書も不要
  • Host ヘッダー分岐は CloudFront Functions / Lambda@Edge で（ネイティブ分岐は path pattern のみ）
フロント配信とテナントルーティングの要。CloudFront のネイティブなマルチテナント機能（比較的新しい）。 ブループリントが共有設定（キャッシュ / セキュリティ / オリジン）の親、distribution tenant が origin_path: "/{{tenantName}}" 等でオリジンを振り分け、connection group がルーティングエンドポイント（サブドメインを CNAME で向ける）。 ルーティング解決は初回のみ実行してキャッシュが推奨（コスト / 性能）。 ボイラープレートの実例: この構成そのもの。CloudFront Function が Host から tenantId を解決し /tenant-config.json をテナント分だけ動的生成。単一 dist を全テナントに配信しつつ clientId 等を実行時解決。
