SBT-AWS ── control / application plane

control plane（非マルチテナント / 管理面）↔ EventBridge ↔ application plane（マルチテナント / ワークロード）

  • SBT-AWS（@cdklabs/sbt-aws、awslabs の OSS、CDK ベース）
  • 提供コンストラクト: ControlPlane / CoreApplicationPlane / CognitoAuth / ProvisioningScriptJob / MockBillingProvider
ここまで個別サービスを見てきたが、それらを組み立てる骨格が AWS 公式から出ている。中核概念は control plane と application plane の分離（SaaS Architecture Fundamentals 白書）。 control plane = オンボーディング・テナント管理・認証・課金・メトリクス・管理ユーザー（全テナント横断で非マルチテナント）。application plane = テナントが使うワークロード（マルチテナント）。 両プレーンは EventBridge（onboardingRequest / provisionSuccess 等）で疎結合に繋がり、片方だけ独立デプロイできる。 位置づけ: 今日紹介したサービス群を「どう束ねてオンボーディング / 運用まで回すか」の設計済みテンプレート。CDK プロジェクトなら親和性が高い。 「自分で全部組むか SBT に乗るか」は規模とチームによる。乗ると control / application の切り分けを強制され設計の軸がぶれにくい。
